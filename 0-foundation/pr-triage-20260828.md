## 2. PR #21 — merge 推奨 ★★★

**実測**: `master` に test-merge した結果、**コンフリクト無し**。
先行 merge 済の #20 と重複する変更は自動的に相殺され、**正味の差分は `PROFILE.md` の 3 行のみ**。

- `2026-05-08` の行を「移行が課題化」(未解決) → 「移行完了 (closed)」に圧縮
- 「進行中の業務継続課題」から完了済の 1 項を削除し、5 項 → 4 項に再採番

**merge すべき理由**: 現在の master は *中途半端に整合していない*。
屋号行・主要ドメイン行は #20 で「移行済」に更新されたのに、
上記 2 箇所は「移行が未完」のまま残っている。
`CLAUDE.md` は `@PROFILE.md` を import するため、この矛盾は
**毎セッション完了済タスクを未完として再提起する**ことになる (Section 7-2 違反の温床)。

**積み残し (この PR の範囲外)**: frontmatter の `updated: 2026-05-11` が
本文の「最終更新: 2026-05-16」と不一致。merge 後に別途修正が要る。

## 3. PR #2 — close 推奨 ★★☆

**前提が陳腐化している**。PR 本文は
「本 PR = 該当 repo に CLAUDE.md / AGENTS.md が **未配置** だったため新規配布」
と述べるが、現在の master には project-specific な `CLAUDE.md` が存在する
(作成は 2026-05-09 の本 PR より後)。前提が成立しない。

さらに `AGENTS.md` の記述内容が現行 `PROFILE.md` と矛盾する:

| 項目 | AGENTS.md (PR #2) | PROFILE.md (現行 master) |
|---|---|---|
| repo 数 | 28+ repo | 46 リポジトリ |
| 公開範囲 | 全 private | **本 repo は public** |
| ルール体系 | R45〜R84 | R1〜R10 (agora#4 が正本) |

矛盾した 2 つの指示書が同居すると、どちらを優先するかで挙動が割れる。
`CLAUDE.md` が既に agora#4 を正本と宣言している以上、
**別番号体系の doctrine を併置する利得より、混乱のコストが上回る** と判断する。

**R8 反論余地**: 「AGENTS.md は Codex / 他 LLM 向けの入口として要る」という
反論は成立し得る。その場合も現状のまま merge するのではなく、
(a) 公開可否を通過した内容に絞り、(b) R 番号を agora#4 系に揃えた
**別 PR として作り直す**のが筋。
